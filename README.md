# Sillapa — ระบบสารสนเทศเพื่อเตรียมจัดการแข่งขันศิลปหัตถกรรมครั้งที่ 74

เว็บ **Progressive Web App (PWA)** สำหรับผู้จัดและโรงเรียน สพป.กาญจนบุรี เขต 4 ใช้วิเคราะห์ข้อมูลครั้งที่ 73 ร่วมกับรายการอ้างอิงครั้งที่ 70 เพื่อเตรียมกิจกรรม กรรมการ และแผนส่งแข่งขันครั้งที่ 74 **ไม่ใช่เว็บรายงานผลการแข่งขันครั้งที่ 74** ไม่ใช่ระบบรับสมัครหรือฐานข้อมูลกลางแบบเรียลไทม์ รองรับติดตั้งเป็นแอปและอ่าน snapshot ที่แคชไว้เมื่อออฟไลน์

## แผนพัฒนาระบบสารสนเทศเตรียมการแข่งขันครั้งที่ 74

การพัฒนาขั้นถัดไปต้อง **ออกแบบให้เป็นระบบสารสนเทศเพื่อเตรียมจัดการแข่งขัน ไม่ใช่เว็บรายงานผลการแข่งขันครั้งที่ 74** และไม่สร้างฐานข้อมูลรับสมัคร/ผลคะแนนคู่ขนานกับ `infobwd/AcademicCompetitionManager`

- **[Information Architecture & Data Contract Design Lock](docs/SILLAPA74_INFORMATION_ARCHITECTURE_DATA_CONTRACT_DESIGN_LOCK.md)** — *PROPOSED / รอผู้ดูแลตรวจรับ*: โครงสร้างระบบเป้าหมาย 6 ส่วน, เมนูมือถือ 4 รายการหลัก, มาตรฐานข้อมูลครั้งที่ 70/73/74, การยืนยันข้อมูล, คีย์เชื่อมโยง, ความปลอดภัย/PII และเกณฑ์ตัวชี้วัด
- **[Information Architecture Delivery Roadmap](docs/SILLAPA74_INFORMATION_ARCHITECTURE_ROADMAP.md)** — *PROPOSED*: ลำดับ IA-0 (เอกสารนี้) → IA-1 (หน้าแรก/เมนู) → IA-2 (ทะเบียนรายการ) → IA-3 (ผู้จัด/กลุ่มเครือข่าย) → IA-4 (โรงเรียน) → IA-5 (กรรมการ/สนาม) → IA-6 (วิเคราะห์ผู้บริหาร)
- [ข้อเสนอ Decision Hub เดิม](docs/SILLAPA74_DECISION_HUB_DESIGN_PROPOSAL.md) ยังใช้เป็นหลักฐานโจทย์ของผู้จัด/โรงเรียน แต่เอกสาร Design Lock ใหม่เป็นข้อเสนอเพื่อทบทวนร่วมกัน **ยังไม่ถือว่าอนุมัติพัฒนา Backend**
- **ขอบเขต PR เอกสาร:** ไม่แก้ `index.html`, JavaScript, Service Worker, กำหนดการแข่งขัน, ฐานข้อมูล, ข้อมูลครั้งที่ 73 หรือระบบรับสมัคร; ยังไม่เปลี่ยนหน้าเว็บจริงหลัง Merge จนกว่าจะมี PR โค้ด IA-1 และผ่านการตรวจรับ

## IA-6 — Dashboard วิเคราะห์และสนับสนุนการตัดสินใจของผู้บริหาร (รอตรวจรับ)

**สถานะ:** พัฒนาใน Branch `feat/ia6-executive-decision-dashboard` · ยังไม่ Merge / ยังไม่เผยแพร่ชุดข้อมูลยืนยันครั้งที่ 74 · [Source Audit, KPI Contract & Acceptance](docs/SILLAPA74_IA6_EXECUTIVE_DECISION_ACCEPTANCE.md)

- หน้า **Dashboard สำหรับผู้บริหาร** (`#executive`) เป็นหน้ารองในหมวด **ภาพรวม** ไม่เพิ่มเมนูหลักใหม่ จึงรักษาเมนูคอมพิวเตอร์ 6 ส่วนและ Bottom Navigation มือถือ 4 ปุ่มจาก IA-1 พร้อมปุ่มทางเข้าจากหน้าแรก
- สรุป **ตัวชี้วัดข้อมูลรับรองจริง 6 ด้าน**: รายการแข่งขันที่ยืนยัน, ภาระส่งตัวแทนที่ตรวจรับ/ภาระที่ใช้สิทธิ์, ทีมที่รับรอง, กรรมการพร้อม/ความต้องการ, ห้องที่จัดสรร/ความต้องการ และประเด็นค้าง · **แสดง `—` ทุกส่วนที่ไม่มีข้อมูลรับรองหรือมีความครอบคลุมไม่ครบ** ไม่ใช้ตัวเลขจากแผนของโรงเรียนหรือจากกรรมการย้อนหลังแทน
- แสดง **ข้อมูลในร่างแยกต่างหาก**: กลุ่มกิจกรรมร่าง 74, กลุ่มจับคู่ย้อนหลังครั้งที่ 70/73 และกลุ่มรอตรวจรายการย่อย โดยระบุชัดว่าไม่ใช่จำนวนรายการย่อยที่เปิดแข่งจริง
- เลือก **ระดับเขต / ระดับกลุ่มเครือข่าย** สำหรับตาราง KPI ที่ผ่านการรับรองเท่านั้น ห้ามนับภาระตัวแทนรวมกับกิจกรรมสมัครตรงแบบ open หรือสมมติทุกกลุ่มมีสิทธิ์ส่งทีมเท่ากัน
- แถบ **แหล่งข้อมูล/รุ่น/เวลา** และ **ข้อควรตรวจ**: สถานะไม่มีข้อมูล รายการรอจับคู่ ขอบเขตไม่ครบ ข้อมูลเก่ากว่า 7 วัน และ PWA offline ที่อาจไม่ทราบคำสั่งถอนเผยแพร่ล่าสุด
- ส่วน **วาระผู้บริหาร** ช่วยติดตามการรับรองกิจกรรม การส่งข้อมูลของกลุ่ม การตรวจกรรมการ/สนาม และขั้นตอนอนุมัติการเผยแพร่ พร้อมกำหนดเบื้องต้น **4 ธ.ค. / 21–24 ธ.ค. 2569** ที่ไม่อ้างว่าเป็นกำหนดตารางสนามจริง
- ส่งออก **CSV สำหรับประชุม** ที่มีเวอร์ชัน แหล่งข้อมูล ขอบเขต ตัวตั้ง/ตัวหาร สถานะ completeness และคำเตือนโดย **ไม่มีข้อมูลส่วนบุคคล** และไม่อ่าน `localStorage`
- `ia6-executive.js` มีตัวตรวจสอบสัญญาข้อมูลสาธารณะ (สำหรับอนาคต) และการเพิกถอน `sillapa-ia6-revocation-v1` แต่ **ยังไม่มีชุดข้อมูลอนุมัติ ไม่โหลด API ไม่สร้างปุ่มเผยแพร่จริง และไม่สามารถล้างข้อมูลที่อยู่ในเครื่องของผู้ใช้คนอื่นได้**
- PWA `sillapa-public-v8-ia6-20261015` รวม `ia6.css`, `ia6-executive.js`; ยังรองรับ IA-2/3/4/5, Dark/Light, Skeleton, Pull-to-Refresh, `#judges` ย้อนหลังและลิงก์เดิม
- **ทดสอบ Local-First:** `node tests/ia2-registry.test.cjs` จนถึง `node tests/ia6-executive.test.cjs`; `python -m http.server 8000` แล้วเปิด `http://localhost:8000/#executive`

**การเผยแพร่ข้อมูลจริงถูกแยกออกเป็น PR และ Gate อนุมัติของผู้จัด/เจ้าของข้อมูล/PDPA**; การ Merge IA-6 จะเพิ่มเพียง UI + contract ไม่ใช่การเปิดเผยฐานข้อมูลหรือข้อมูลกรรมการ/นักเรียนครั้งที่ 74

## IA-5 — กรรมการและสนามแข่งขัน (Local-First · Merge PR #10 แล้ว)

**สถานะ:** Merge PR #10 (Commit `12e4ba3`) · [IA-5 Source Audit & Acceptance](docs/SILLAPA74_IA5_JUDGE_VENUE_READINESS_ACCEPTANCE.md)

- หน้าหลัก **กรรมการและสนามแข่งขัน** (`#venue`) เปลี่ยนจากหน้าแจ้งสถานะรอข้อมูลเป็น **โต๊ะวางแผนผู้จัด** โดยใช้ร่างกิจกรรม IA-2 จำนวน 56 กลุ่มรายการและข้อมูลกรรมการครั้งที่ 73 แบบสรุปจำนวนเท่านั้น ไม่เพิ่มรายชื่อบุคคลใหม่
- แยกข้อมูลชัดเจน: **กรรมการแต่งตั้งจริงครั้งที่ 74 = —, สนาม/ห้องที่ยืนยัน = —** เพราะยังไม่มีแหล่งข้อมูลสาธารณะที่ได้รับอนุมัติ; ค่า **0** แสดงได้เฉพาะข้อมูลที่มีหลักฐานจำนวนศูนย์ ไม่ตีความความว่างเป็นศูนย์
- ตารางย้อนหลังตามหมวด: กิจกรรมร่าง 74 เทียบข้อมูลครั้งที่ 73 จำนวนรายการที่มีกรรมการ จำนวนกรรมการไม่ซ้ำ *ภายในกลุ่ม* จำนวนตำแหน่ง และสัญญาณโรงเรียนกรรมการเคยร่วมแข่ง (เป็นเพียงข้อสังเกต ไม่ใช่คำวินิจฉัย)
- แผนเฉพาะอุปกรณ์ `sillapa74:judge-venue-planning:v1`: ประมาณการจำนวนกรรมการ ห้อง และความจุคนต่อห้อง **แยกระดับกลุ่ม/ระดับเขต** โดยไม่ยืนยันว่ากิจกรรมนี้เปิดแข่งในระดับดังกล่าว; ติ๊กธงให้ตรวจเรื่องผู้ควบคุมทีม โรงเรียนร่วมแข่ง เวลาซ้อน ความพร้อม และความจุห้อง/อุปกรณ์
- ตัวกรองกลุ่ม ค้นหา เฉพาะรายการมีข้อสังเกต/ขาดประมาณการ แสดงกิจกรรมครั้งละ 12 รายการ และส่งออก CSV แผนที่กรองได้โดยไม่มีชื่อคน พร้อมป้องกันสูตรอันตราย
- ตัวเลขรวมประมาณการคน/ห้องเป็น **—** จนกว่าจะกรอกครบทุกกิจกรรมในร่างของระดับที่เลือก; การกรอกเป็นเพียงแผนในเครื่อง ไม่ใช่ข้อกำหนด/คำสั่งแต่งตั้ง/จำนวนพื้นที่รับรอง
- แยกรายชื่อกรรมการครั้งที่ 73 ไปไว้ที่ `#judges` เดิม ไม่เพิ่มการคัดลอกชื่อมาเป็นรายชื่อ 74; การจัดสรรจริง สถานะรับรอง คำสั่งแต่งตั้ง ตารางสนามและเกียรติบัตรยังเป็นหน้าที่ `infobwd/AcademicCompetitionManager`
- **No core API**, no student/teacher/judge PII collection, no shared database; validator `sillapa-ia5-public-v1` เป็นเพียงข้อเสนอสำหรับชุดข้อมูลสาธารณะในอนาคตและไม่ได้โหลดข้อมูลจริง
- PWA `sillapa-public-v7-ia5-20261015` แคช `ia5-judge-venue.js` + `ia5.css`; Dark/Light, Mobile Bottom Navigation, More sheet, Skeleton, Pull-to-Refresh และ IA-1 ถึง IA-4 ยังคงอยู่
- **ทดสอบ Local-First:** `node tests/ia2-registry.test.cjs`, `node tests/ia3-readiness.test.cjs`, `node tests/ia4-school-workspace.test.cjs`, `node tests/ia5-judge-venue.test.cjs`; เปิด `http://localhost:8000/#venue` ด้วย `python -m http.server 8000`

**ข้อควรระวัง:** แผนนี้อยู่ในเครื่องเดียว ไม่ซิงก์ ไม่ใช่คำสั่งกรรมการ/กำหนดการสนามจริง ข้อมูล 73 ไม่ได้ยืนยันสถานะ 74 และไม่มีการเปลี่ยน Production ครั้งที่ 73 หรือระบบแข่งขันหลัก

## IA-4 — เตรียมแข่งขันของโรงเรียน (Local-First · Merge PR #9 แล้ว)

**สถานะ:** Merge PR #9 (Commit `5116bb9`) · [IA-4 Source Audit & Acceptance](docs/SILLAPA74_IA4_SCHOOL_WORKSPACE_ACCEPTANCE.md)

- หน้า **เตรียมแข่งขันของโรงเรียน** (`#prep`) เพิ่มสรุปกิจกรรมและเช็กลิสต์ในแผนของโรงเรียนที่เลือก พร้อมแจ้งชัดเจน **“แผนในเครื่องนี้ · ไม่ใช่ใบสมัคร”** ไม่อ้างว่าบันทึกผลลงระบบแข่งขันหลัก

- แสดงเช็กลิสต์ 3 เรื่องสำหรับแต่ละกิจกรรม ได้แก่ ตรวจประกาศเกณฑ์ ยืนยันระดับชั้น/ความพร้อมของทีม และเตรียมเอกสารตามประกาศ · เครื่องหมายถูกเป็นการเตรียมงานส่วนตัว ไม่ใช่การตรวจรับจากเขต
- ยังคงการเลือกโรงเรียน การดูผลครั้งที่ 73 รายการร่าง 74 จากครั้งที่ 70/73 การเพิ่มกิจกรรม เลือกระดับชั้น คัดลอก/ส่งออกไฟล์ วันที่วางแผน Dark/Light, Splash/Skeleton, PWA, Bottom Navigation 4 ปุ่ม และข้อมูลย้อนหลัง

- ยังไม่มี `school_id` ทางการที่จับคู่ได้หรือสิทธิ์ลิงก์เข้าระบบสมัครแข่งขันครั้งที่ 74; ชื่อโรงเรียนที่เลือกเป็นเพียงป้ายชื่อในแผนเครื่องนี้ มิใช่การยืนยันสิทธิ์
- Cache shell รุ่น `sillapa-public-v6-ia4-20261015` พร้อม `ia4.css` และ `ia4-workspace.js` · **ทดสอบ Local-First:** `node tests/ia4-school-workspace.test.cjs`, `node tests/ia3-readiness.test.cjs`, `node tests/ia2-registry.test.cjs` แล้ว `python -m http.server 8000` เปิด `http://localhost:8000/#prep`

**ข้อควรระวัง:** การล้างข้อมูลเว็บในเบราว์เซอร์อาจทำให้แผนใหม่สูญหาย ต้องคัดลอก/ส่งออกสำรองก่อน; ยังไม่มีการซิงก์ข้ามเครื่องหรือระบบสมัครจริง และไม่แก้ Production ครั้งที่ 73

- ตัวตรวจสอบ `ia3-readiness.js` ปฏิเสธรอบแข่งขันไม่ถูกต้อง ข้อมูลยังไม่ได้เผยแพร่ ขอบเขตข้อมูลไม่ครบ รหัสซ้ำ และฟิลด์นอกสัญญาที่เสี่ยงต่อข้อมูลส่วนบุคคล **ไม่เรียก API และไม่เชื่อมฐานข้อมูลจริง**
- อ้างอิงวันที่ **4 ธ.ค. 2569** เป็นกำหนดส่งตัวแทน ไม่ใช่ปิดรับสมัครทั่วไป และ **21–24 ธ.ค. 2569** ยังเป็นวันแข่งขันระดับเขตเบื้องต้น
- PWA แคชไฟล์ IA-3 แบบ Public Shell รุ่น `sillapa-public-v5-ia3-20261015`; Navigation IA-1, ทะเบียน IA-2, ข้อมูลย้อนหลัง, Dark/Light, Pull-to-Refresh และแผนโรงเรียนเดิมยังคงอยู่
- ทดสอบ Local-First: `node --check ia3-readiness.js`, `node tests/ia3-readiness.test.cjs`, `node tests/ia2-registry.test.cjs`; เปิด `http://localhost:8000/#readiness` ด้วย `python -m http.server 8000` เพื่อทดสอบหน้าเว็บ ห้ามถือว่าผลจำลองผ่านเท่ากับการตรวจรับบนอุปกรณ์จริง

**ข้อสำคัญ:** `AcademicCompetitionManager` ยังเป็นเจ้าของข้อมูลสมัคร/ทีม/ส่งตัวแทน/สิทธิ์/รับรอง การนำชุดข้อมูลจริงมาเผยแพร่ต้องมี PR และอนุมัติด้านสัญญาข้อมูล/PDPA แยกต่างหาก ไม่แก้ Production ครั้งที่ 73 และข้อมูลจริงจากระบบหลักยังต้องอนุมัติการเผยแพร่แยกต่างหาก

## IA-2 — ทะเบียนรายการแข่งขันครั้งที่ 74 (อ่านอย่างเดียว)

**สถานะ:** Merge PR #7 แล้ว (Commit `e425014`) · [คู่มือ IA-2 และเกณฑ์ตรวจรับ](docs/SILLAPA74_IA2_ACTIVITY_REGISTRY_ACCEPTANCE.md)

- หน้าหลัก **รายการแข่งขัน 74** เปลี่ยนจากเน้นตารางเทียบข้อมูลเป็น **ทะเบียนค้นหาได้** โดยจัดโครงสร้างกลุ่มกิจกรรม → ชื่อกิจกรรมในร่าง → **รายการย่อยและระดับชั้นจากครั้งที่ 70 หรือ 73**
- ข้อมูลที่ตรวจสอบจาก Repository: **56 กลุ่มกิจกรรมในร่าง / 17 หมวด** แยกเป็น **25 กลุ่มอ้างอิงครั้งที่ 70 (63 รายการย่อย/ระดับชั้น)**, **29 กลุ่มอ้างอิงครั้งที่ 73 (83 รายการย่อยตามชื่อเดิม)** และ **2 กลุ่มรอตรวจสอบ** (กลุ่มนาฏศิลป์, กลุ่ม Soft Power)
- ตัวกรอง: **กลุ่มกิจกรรม / ระดับชั้นต้นทาง / ชุดข้อมูลย้อนหลัง 70–73 / สถานะร่างหรือยืนยัน / ระดับกลุ่ม–เขต** ร่วมกับการค้นหาชื่อรายการ รหัสต้นทาง หรือระดับชั้น ปุ่มล้างตัวกรอง และขยาย/ย่อรายละเอียด
- ในกรณีที่กรอง **“ยืนยันแล้ว” / “ระดับกลุ่ม” / “ระดับเขต”** จะไม่แสดงรายการสมมติ เนื่องจากยังไม่มีข้อมูลที่ผู้จัดรับรองอย่างเป็นทางการ
- แสดงเลขรหัสต้นทางอย่างเช่น `030` (รหัสครั้งที่ 70) ให้ชัดว่า **ไม่ใช่รหัสกิจกรรมการแข่งขันครั้งที่ 74** และมีลิงก์แหล่งอ้างอิง
- ดาวน์โหลด **CSV ทะเบียนรายการในร่าง** ได้ตามตัวกรอง ประกอบด้วย 15 คอลัมน์; เมื่อไม่กรองได้ 149 แถวรวมส่วนหัว (63 รายการย่อยจาก 70 + 83 รายการย่อยจาก 73 + 2 กลุ่มรอตรวจสอบ)
- หน้าวิเคราะห์ **73 ↔ 74 แบบเดิมยังเปิดได้** ด้วยส่วนกาง/ยุบด้านล่าง ไม่มีการลบสถิติย้อนหลังหรือฐานข้อมูลเดิม
- PWA ปรับแคชเป็น `sillapa-public-v4-ia2-20261015` พร้อมไฟล์ `ia2.css` และ `ia2-registry.js` รองรับหน้าเดิมเมื่อออฟไลน์
- **ทดสอบ Local-First โดยไม่ต้องติดตั้งแพ็กเกจ:** `node tests/ia2-registry.test.cjs` แล้ว `python -m http.server 8000` เปิด `http://localhost:8000/#next` เพื่อทดสอบหน้าจอจริง

**ข้อจำกัดที่ต้องย้ำ:** แหล่งรายการครั้งที่ 70 เป็นบัญชีข้อมูลย้อนหลังจาก สพป.ร้อยเอ็ด เขต 3 ไม่ใช่ประกาศครั้งที่ 74 ของ สพป.กาญจนบุรี เขต 4; การสมัคร โควตาตัวแทน เกณฑ์ และระดับชั้นจริงต้องยืนยันจากระบบหลัก/ประกาศเขตก่อนนำไปใช้จริง

## IA-1 — หน้าแรกและเมนูหลักสำหรับเตรียมการแข่งขันครั้งที่ 74

## กำหนดการแข่งขันครั้งที่ 74 (เพื่อการวางแผน)

- **ภายใน 4 ธันวาคม 2569:** กลุ่มเครือข่ายส่งผลและรายชื่อทีมตัวแทนเข้าสู่ระดับเขต (ไม่ใช่วันแข่งขันระดับกลุ่ม)
- **ประมาณ 21–24 ธันวาคม 2569:** ช่วงที่คาดว่าจะจัดการแข่งขันระดับเขต (กำหนดเบื้องต้น; วัน/เวลา/สนามแยกรายกิจกรรมรอประกาศ)
- วันแข่งขันระดับกลุ่ม วันเปิด/ปิดสมัคร และกำหนดรายกิจกรรมอื่น ๆ ยังไม่ทราบ ห้ามอนุมาน

หน้าเว็บแสดงกำหนดการเดียวกันใน **ภาพรวม / เทียบครั้งที่ 73–74 / เตรียมแข่งขันครั้งที่ 74** โดยอ้าง HTML template เดียว เพื่อลดความคลาดเคลื่อนในการแก้ไข

**แนวทางยกระดับเป็นเว็บฐานข้อมูลสำหรับผู้จัดและผู้แข่งขัน:** [ข้อเสนอ Sillapa 74 Decision Hub](docs/SILLAPA74_DECISION_HUB_DESIGN_PROPOSAL.md). เอกสารเป็น `PROPOSED`; ยังไม่มีการเชื่อมฐานข้อมูลจริง/แก้ Backend ของระบบหลัก

## บทบาทของระบบ (Planning Intelligence ไม่ใช่ผลแข่งขันครั้งที่ 74)

**ชื่อ/วัตถุประสงค์:** ระบบสารสนเทศเพื่อเตรียมจัดการแข่งขันงานศิลปหัตถกรรมนักเรียน ครั้งที่ 74 สพป.กาญจนบุรี เขต 4 มีหน้าที่ช่วยผู้จัดและโรงเรียนวิเคราะห์ข้อมูลย้อนหลัง วางแผนกิจกรรม กรรมการ และความพร้อม **ไม่ใช่ระบบรายงานผลการแข่งขันครั้งที่ 74 ไม่ใช่ระบบรับสมัคร และไม่ใช่ประกาศที่ยืนยันระดับชั้นของครั้งที่ 74**

**การใช้ครั้งที่ 70 สำหรับกิจกรรมที่นำกลับมา:** ถ้าร่างครั้งที่ 74 เลือกใช้กิจกรรมจากครั้งที่ 70 ต้องนำมา **ครบทุกประเภท/ทุกรายการย่อย/ทุกระดับชั้น** ที่ปรากฏในรายการครั้งที่ 70 ที่ตรวจสอบ ไม่ตัดให้เหลือเพียงระดับชั้นเดียว และไม่อนุมานว่าครั้งที่ 74 เปิดรับสมัครแล้ว
- เก็บรายการอ้างอิง 25 กลุ่มกิจกรรม รวม **63 รายการย่อยตามระดับชั้น** ใน `round70-catalog.js` จากบัญชีรายการศิลปหัตถกรรมครั้งที่ 70 ที่เผยแพร่โดย สพป.ร้อยเอ็ด เขต 3: https://sillapa65.vichakan.net/sp-ret3/?cat=7&file=view_all&name=category
- รายการใหม่อีก 2 กลุ่ม (**กลุ่มนาฏศิลป์ และกลุ่ม Soft Power**) ยังไม่มีชื่อย่อยตรงตัวที่ยืนยันได้ จึงแสดง **รอตรวจสอบ** ไม่เติมระดับชั้นคาดเดา
- หน้า **73 vs 74** และ **เตรียม 74** แสดงรายการอ้างอิงตามระดับชั้นทั้งหมด รวมในไฟล์ CSV ที่ดาวน์โหลดได้ โดยติดป้ายว่าเป็นข้อมูลครั้งที่ 70 **ยังไม่ใช่เกณฑ์/รายการที่ประกาศครั้งที่ 74**
- รายการผลครั้งที่ 73 เป็น snapshot ย้อนหลัง ไม่เปลี่ยนแปลงข้อมูลผลการแข่งขันหรือคณะกรรมการเดิม

## การรีเฟรชด้วยท่าทางบนมือถือ

เมื่ออยู่ด้านบนสุดของหน้าเว็บ ให้ใช้นิ้ว **ดึงลง** จนเห็นข้อความ **“ปล่อยเพื่อรีเฟรชข้อมูล”** แล้วปล่อย ระบบจะขออัปเดต Service Worker แล้วโหลดหน้าใหม่ ขณะออนไลน์อ่าน HTML ล่าสุดก่อนแคช หากออฟไลน์อาจเห็นข้อมูลเดิมในแคช การดึงเพื่อรีเฟรช **ไม่ได้ซิงก์ฐานข้อมูลจริง** (เว็บนี้เป็น static snapshot)

ท่าทางนี้ไม่ทำงานขณะเลื่อนในโมดัล/Bottom Sheet หรือเริ่มสัมผัสจากปุ่ม/ช่องค้นหา และอาจแตกต่างตามระบบ iOS/Android ที่มี native pull-to-refresh อยู่แล้ว

## PWA — ติดตั้งลงหน้าจอหลัก (เวอร์ชันรอตรวจรับ)

ตัวเว็บมี Web App Manifest และ Service Worker รองรับติดตั้งจาก URL แบบ **HTTPS** (GitHub Pages) หรือ **localhost** เพื่อทดสอบในเครื่อง

**จากภายในหน้าเว็บ** จะมีแนะนำ **“ติดตั้ง Sillapa ไว้บนหน้าจอหลัก”** สำหรับมือถือ พร้อมปุ่ม **“ดูวิธีติดตั้ง”**; เมื่อรองรับ native install prompt ปุ่มจะเป็น **“ติดตั้งแอป”** และกดเพื่อขอการติดตั้งได้ทันที ผู้ใช้ปิดคำแนะนำได้ และกด **“ติดตั้งเป็นแอป”** ที่ส่วนท้ายเว็บเพื่อเปิดคำแนะนำอีกครั้ง

### วิธีติดตั้ง

- **iPhone/iPad:** เปิดเว็บไซต์ใน Safari (หรือเบราว์เซอร์ที่รองรับ Add to Home Screen) → แตะ **แชร์ (Share)** → **เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)** → **เพิ่ม** หากไม่พบเมนูให้เลื่อนดูในรายการแชร์
- **Android (Chrome):** เปิดเว็บ → กด **“ติดตั้งแอป”** หากเบราว์เซอร์อนุญาต หรือเมนู **⋮ → ติดตั้งแอป / เพิ่มไปยังหน้าจอหลัก**
- **คอมพิวเตอร์ (Chrome/Edge):** ใช้ไอคอนติดตั้งที่แถบที่อยู่หรือเมนูเบราว์เซอร์ (ขึ้นกับการรองรับ)
- **หลังติดตั้ง:** เปิดจากไอคอน **Sillapa 74** ได้เหมือนแอป และปุ่มเชิญติดตั้งจะไม่รบกวนในโหมด standalone

| `index.html` | หน้าเว็บเดิม + link PWA + ส่วนแนะนำติดตั้ง/แจ้งอัปเดต |
| `manifest.webmanifest` | ชื่อแอป ไอคอน `display=standalone` และ `start_url/scope=./` |
| `icons/icon-192.png`, `icons/icon-512.png` | ไอคอนสำหรับ Chromium / Android |
| `icons/apple-touch-icon.png` | ไอคอนหน้าจอหลัก iPhone/iPad ขนาด 180 |
| `pwa.css`, `pwa.js` | หน้าตาติดตั้ง คำแนะนำตามอุปกรณ์ การตรวจเวอร์ชัน |
| `sw.js` | Service Worker เก็บไฟล์สาธารณะสำหรับออฟไลน์ และอ่าน HTML แบบ network-first |

**Offline:** ต้องเปิดเว็บสำเร็จขณะมีอินเทอร์เน็ตอย่างน้อยหนึ่งครั้งเพื่อบันทึกแคช หลังจากนั้นเข้าหน้า Dashboard ที่เคยโหลดได้โดยไม่ต่อเน็ต ข้อมูลใน `index.html` เป็น **snapshot** ไม่สด/ไม่ซิงก์กับฐานข้อมูล; Google Fonts อาจใช้ฟอนต์สำรองเมื่อออฟไลน์ แผนโรงเรียนใน `localStorage` ยังอยู่เฉพาะอุปกรณ์/เบราว์เซอร์นั้น

**Updates:** HTML ใช้ **network-first** เมื่อออนไลน์เพื่อลดปัญหาหน้าเก่าค้าง; หาก Service Worker เปลี่ยน จะมีข้อความ **“มีเวอร์ชันใหม่”** ให้ผู้ใช้กดรีโหลด เวลาปรับรายการ precache หรือไฟล์ UI ต้องเปลี่ยนค่า `CACHE_NAME` ใน `sw.js` (เพิ่มเวอร์ชัน) และตรวจการเผยแพร่ผ่าน GitHub Pages ให้เสร็จก่อน

**ขอบเขตความปลอดภัย:** Service Worker ดักเฉพาะคำขอ GET ภายใน path ของเว็บนี้ และแคชเฉพาะไฟล์สาธารณะ ไม่แคช API รับสมัคร/ข้อมูลส่วนบุคคล/บริการภายนอก; การติดตั้งไม่ได้ทำให้ข้อมูลแผนของทุกโรงเรียนรวมศูนย์

**เกณฑ์ทดสอบ:** [PWA Acceptance Checklist](docs/PWA_ACCEPTANCE.md) — ตรวจ Android, iPhone, desktop, Offline/Online, data freshness และการเปิด/ปิดคำแนะนำติดตั้งก่อน Merge

## การปรับ UX สำหรับมือถือ (Splash / Skeleton)

- **ลดการซูมด้วยนิ้ว:** `viewport` จำกัด pinch/double-tap zoom บนเบราว์เซอร์มือถือ รักษาการเลื่อนหน้าและปุ่มตามปกติ; ปรับ `input/select/textarea` เป็นอย่างน้อย 16px บนมือถือเพื่อไม่ให้ iPhone ซูมเมื่อโฟกัสช่องกรอก บางเบราว์เซอร์หรือฟีเจอร์ช่วยการเข้าถึงอาจยังอนุญาตให้ซูมได้
- **Splash Screen:** แสดงตอนเข้าเว็บครั้งแรกของการโหลดหน้าเว็บ พร้อมชื่อการแข่งขันและหน่วยงาน ปิดเมื่อเรนเดอร์ข้อมูลหลักครบ ไม่หน่วงเกินความจำเป็น (ขั้นต่ำประมาณ 0.4 วินาที ยกเว้นผู้ใช้ตั้งค่าลดการเคลื่อนไหว)
- **Fail-safe:** ถ้าเริ่มต้นหน้าเว็บผิดพลาด มีข้อความแจ้งและปุ่มโหลดใหม่หลัง 7 วินาที ไม่แสดงสปินเนอร์ตลอดไป
- **Skeleton:** มีโครงร่างโหลดสำหรับ 8 หน้า (`overview/reps/groups/schools/acts/judges/next/prep`) ใช้ `data-loading` และ `aria-busy`; ซ่อนเมื่อข้อมูลพร้อม ในเว็บ Static นี้ทุกหน้าสร้างจากข้อมูลในไฟล์ จึง **ไม่เพิ่มดีเลย์ปลอม** เมื่อสลับหน้าที่มีข้อมูลพร้อมแล้ว
- **ขอบเขต:** ยังคงข้อมูลการแข่งขันเดิมทุกแถว ไม่แตะ Backend หรือระบบรับสมัคร `AcademicCompetitionManager`

ดูเกณฑ์ตรวจสอบก่อน Merge ที่ [UI Loading Acceptance](docs/UI_LOADING_ACCEPTANCE.md)

## สิ่งที่มีในหน้าเว็บ

- ภาพรวมผลแข่งขันครั้งที่ 73 พร้อมเหรียญ คะแนน และตัวแทนเขต
- รายกลุ่มกิจกรรม รายโรงเรียน และรายรายการแข่งขัน
- มุมมองกรรมการตัดสินและข้อสังเกตที่ควรตรวจสอบเพิ่มเติม (ไม่ใช่ข้อยุติการขัดกันแห่งผลประโยชน์)
- เปรียบเทียบข้อมูลครั้งที่ 73 กับ **ร่าง** รายการครั้งที่ 74
- เครื่องมือสำหรับครูเลือกโรงเรียนและวางแผนส่งแข่งขัน รวมถึงคัดลอก/ส่งออก CSV และรายงาน HTML

## ขอบเขตข้อมูลและข้อจำกัด

- ข้อมูลสถิติและรายชื่อที่แสดงถูกฝังอยู่ในไฟล์ `index.html` เป็น **snapshot** ไม่ใช่ข้อมูลสดจากระบบรับสมัครหรือฐานข้อมูลการแข่งขัน
- ร่างรายการครั้งที่ 74 และเกณฑ์/ตัวเลขอ้างอิงใช้เพื่อประกอบการวางแผน **ต้องตรวจสอบกับประกาศทางการก่อนใช้งานจริง**
- **GitHub Pages ไม่มี Backend/Database ของแอปนี้:** แผนที่ผู้ใช้สร้างผ่านหน้าเว็บจะเก็บไว้ใน `localStorage` ของเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ได้ส่งแผนไปรวมทั้งเขต และไม่ใช่ระบบร่วมแก้ไขหลายโรงเรียน
- ฟีเจอร์ออนไลน์ที่อาศัยบริการเฉพาะแพลตฟอร์มต้นแบบจะไม่ทำงานบน GitHub Pages โดยไม่ได้พัฒนา Backend เพิ่ม
- Repository และ GitHub Pages เป็นสาธารณะ: หน้านี้มี **ชื่อกรรมการและโรงเรียนจากไฟล์ที่ได้รับ** ควรตรวจสอบสิทธิ์และความเหมาะสมก่อนเผยแพร่/ส่งต่อ และไม่ควรเพิ่มข้อมูลส่วนบุคคลที่ไม่จำเป็น
- Repo นี้แยกจาก `infobwd/AcademicCompetitionManager` โดยไม่แก้ข้อมูลผลการแข่งขันเดิม รายชื่อครู นักเรียน หรือระบบรับสมัครในโปรเจ็กต์นั้น

## ทดสอบในเครื่อง (Local-first)

เปิด `index.html` ด้วยเบราว์เซอร์ หรือเปิดจากโฟลเดอร์ Repository ด้วยคำสั่ง:

```bash
python -m http.server 8000
```

จากนั้นเปิด http://localhost:8000/ ควรทดสอบทั้งมือถือ แท็บเล็ต คอมพิวเตอร์ เมนูค้นหา ตัวกรอง การเปิดรายละเอียด การจัดแผนและการดาวน์โหลดไฟล์

**ไม่ต้องติดตั้ง npm และไม่ต้อง build:** หน้าเนื้อหาหลักยังอยู่ใน HTML เดียว ส่วน PWA เพิ่มไฟล์ static CSS/JS, manifest, ไอคอนและ Service Worker; ฟอนต์จาก Google Fonts ใช้ได้เมื่อเชื่อมต่ออินเทอร์เน็ต
